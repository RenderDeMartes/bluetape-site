How we approach it

Two rigs, one character

Most game characters have an animation rig in Maya and a runtime skeleton in Unreal. We build both so they agree: the animation rig drives an export skeleton that is checked before it ever reaches the engine.

Control Rig where it earns it

Control Rig is useful for in-engine animation, procedural adjustments and fixes after import. We add it where the project actually needs it rather than duplicating the Maya rig for its own sake.

Found in Maya, not in the engine

Joint count, orientation, bind pose, naming and morph target names are all validated before delivery. Problems that would otherwise surface during integration get fixed in Maya first.

A good fit when
  • Imports into Unreal keep breaking or drifting
  • You want animators to work in engine with Control Rig
  • Characters need to share an existing project skeleton
  • Correctives and morph targets need to survive the export
FAQ

Questions studios ask

Do you set up Control Rig in Unreal Engine?

Yes, for in-engine animation, procedural adjustments and post-import fixes, where the project needs it.

Can you rig to our existing Unreal skeleton?

Yes. Rigging to a shared project skeleton keeps animation compatible across characters.

Do you also build the Maya animation rig?

Yes. Usually the Maya rig drives the export skeleton, and both are delivered together.
